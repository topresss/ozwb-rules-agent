# 安全策略

## 报告漏洞

如果你发现安全漏洞，请不要在公开 Issue 中提交。推荐通过以下方式私下报告：

- 使用 GitHub 的[私密漏洞报告](https://github.com/yifan4243-sketch/OZON_MCP/security/advisories/new)功能

我们会尽快确认并修复。

## 密钥泄露处理

如果你不小心提交了真实的 Ozon API 凭据：

1. 立即在 Ozon 后台撤销该密钥并生成新密钥
2. 清理 Git 历史中的敏感信息
3. 检查是否有异常 API 调用记录

## 安全最佳实践

- 为 MCP Server 单独创建 Ozon API 密钥，使用最小权限
- 定期在 Ozon 后台轮换 API Key
- 不要将 `.env` 文件提交到版本控制
- 不要在生产日志中输出 API 响应体（可能包含敏感业务数据）
- 在本地或受信任的服务器上运行 MCP Server
- 生产环境建议通过 Docker 等容器化方式运行，隔离环境变量

## 本项目的安全措施

- 所有凭据使用 `pydantic.SecretStr` 保护，不会被 `repr()` 或 `print()` 泄露
- OAuth 认证失败时故意不记录响应体，防止凭据回显
- 写入和破坏性 API 操作需要额外的确认参数
- 订阅权限不足时会在本地拦截，不发送 HTTP 请求（节省配额）
- 集成测试运行前会主动清除环境变量中的凭据

## 已知限制

- 当前版本不支持多用户认证隔离
- MCP stdio 传输模式下，Server 进程与客户端在同一主机上运行
- 不支持 HTTPS 传输层加密（MCP stdio 为本地进程间通信）
